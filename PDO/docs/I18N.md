# Languages and translations

The application supports English (`en`), French (`fr`), and Kinyarwanda (`rw`). English is the default. It does not infer a different default from the browser's `Accept-Language` header.

## Files

- `resources/lang/en.php`, `fr.php`, `rw.php`: matching PHP arrays containing the interface wording, status labels, role labels, month names, and day names.
- `app/Support/Translation.php`: catalog loading, `t()`, label helpers, and date/number formatting.
- `includes/languageSwitcher.php`: shared selector in public and authenticated headers.
- `actions/language.php`: validated POST handler for language selection.
- `includes/bootstrap.php`: session initialization, safe return paths, `e()`, and `money()`.
- `assets/app.js`: localized product hints and loan estimates using templates supplied by the header.

The session preference takes priority over the `mlms_language` browser cookie; otherwise the application uses English. The cookie lasts one year and is scoped to the application path. It uses HttpOnly and SameSite=Lax, plus Secure on HTTPS. Sign-in and sign-out preserve the preference. No database migration or account-language column is required; the choice applies to that browser.

The selector submits with CSRF protection. It returns to an allowlisted local page and preserves query parameters such as record IDs and report filters. Switching reloads the screen; save an unfinished form before switching.

## Add or change text

Use a readable English sentence as the key and add it in the same position in each catalog:

```php
// en.php
'Loan details' => 'Loan details',
// fr.php
'Loan details' => 'Détails du prêt',
// rw.php
'Loan details' => 'Ibisobanuro by’inguzanyo',
```

Render translated text through the escaping helper:

```php
<h1><?= e(t('Loan details')) ?></h1>
```

Use named placeholders for variable information instead of constructing sentences from fragments:

```php
<?= e(t('Loan #:id', ['id' => $loan['loan_id']])) ?>
```

Keep the same placeholders in every translation. Catalog values contain plain text, never HTML. `t()` returns text; `e()` escapes it for HTML. Missing wording falls back to the English catalog, then to the supplied key.

Existing services return English validation messages. The renderers translate those messages, including a small set of parameterized legacy messages listed in `translation_templates()`. Prefer `t('Message with :value', ['value' => $value])` when adding presentation text; if a new interpolated service error must be translated at render time, register its template and add it to all catalogs.

## Labels and formatting

Use these helpers for stored codes and display values:

```php
status_badge($loan['loan_status']); // Escaped badge with a translated status label
status_label('COMPLETED');         // Plain translated label
role_label('CUSTOMER');
enum_label('MOBILE_MONEY');
audit_label('LOAN_APPROVED');
money($loan['outstanding_balance']);
format_number($count);
format_date($loan['created_at'], true);
```

Status, role, payment-method, and audit values in the database remain stable codes. French money displays use a space for thousands and a comma for decimals. Kinyarwanda uses a point for thousands and a comma for decimals; English uses commas for thousands and a decimal point. Browser estimates follow the same conventions as server-rendered amounts. Dates use translated months/days and the existing Africa/Kigali timezone. Date inputs retain ISO values and numeric form submissions retain their existing format.

Product names/descriptions, personal information, document filenames, loan purposes, review notes, and borrower messages stay in their original wording. Do not pass those values through `t()` or translate them automatically.

For new JavaScript interface text, add a named template in `javascript_translations()` and all catalogs, then read it from the existing `app-translations` JSON block. Keep calculations based on numeric values; localize the displayed result only.

## Verify

From the repository root:

```bash
php PDO/tests/i18n_catalog_test.php
python3 PDO/tests/workflow_test.py
RUN_BROWSER_QA=1 python3 PDO/tests/workflow_test.py
```

The catalog check verifies matching keys, placeholders, fallback behavior, and representative translations/formatting. Integration checks cover selected screens and validation in French/Kinyarwanda, English default, cookies, sign-in/out persistence, and safe return paths. Optional Chrome checks exercise the selector and desktop/mobile layouts; screenshots are written to `/tmp/mlms-ui-preview`.

When adding a screen, add its path to `language_return_path()` in `includes/bootstrap.php` so switching languages returns to it. When changing translations or layout, inspect longer French and Kinyarwanda labels at mobile widths and review receipt print preview.
